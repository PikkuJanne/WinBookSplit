# Interactive plan and generated-PDF controls

Run through `tests/run_tests.py --layer ux` with both actual supported
`--shell-path` values and the real pinned `--calibre-path`. The full gate includes
this stage. Use isolated developer Python (`-I -B`) and a new external report path.

The 28 native controls comprise thirteen copied, byte-identical application cases
under each actual PS5.1/PS7 host and two direct-engine real EPUB/AZW3 working-PDF
controls. No private books or source modifications are used. A twelve-page authored
nested PDF includes front matter, parent opening pages and a childless parent.
Held console observations prove no chapter reservation/publication before consent;
complete raw logs bind the displayed canonical plan, replies, native result and
reopened ordered physical-page content. Cancel, blank, EOF, invalid consent,
explicit fallback, NonInteractive, Preview and pending-input timeout are separate
controls. Actual source/neighbor/prior identities, policies and known owned cleanup
are required.

Preview creates no disk console log by design. Its control binds the single
authoritative stdout outcome and embedded engine plan to the actual host exit,
captured streams, copied application bytes, immutable source identity, complete
human plan and unchanged output base. It claims no separately persisted child
transport or console log. NonInteractive execution still requires its real log.

A pending-input timeout may retain zero or one cancelled, zero-output engine
frame when closing stdin races forced shutdown. The authoritative application
outcome must remain timeout/130, with TimedOut, stopped tree, both EOFs, stopped
writer, zero queued/written replies and zero publication. A success or execution
frame is rejected, regardless of the final application classification.

Real ebook manual cases decline opening, and direct-engine controls independently
read the requested working PDF before starts and at confirmation, then prove its
owned cleanup after cancellation. These are not PDF viewer/Explorer opening,
human keyboard, package, rendered-fidelity or clean-OS tests. Actual GUI opt-in
opening is recorded separately. No automatic viewer opening is simulated.

`validate_ux_report.py` independently rejects missing source/runtime/stream bindings,
conflicting frames, unsafe coverage, absent consent, false no-write or cleanup
claims, and changed displayed/output metadata. `test_ux_receipt.py` contains
synthetic validator mutations; it does not certify native acceptance. Failed
native workspaces and raw controls remain retained when shutdown is unproved.
