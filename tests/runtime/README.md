# Runtime and converter acceptance

Run this layer with the explicit fresh developer Python, both supported shell
paths, an external new report and the recorded Calibre 9.15.0 executable:

```powershell
& $DeveloperPython -I -B tests/run_tests.py --layer runtime --shell-path $PS51 --shell-path $PS7 --calibre-path $Calibre --report $NewExternalReport
```

Thirty-three actual whole application processes cover missing/native non-Python/
real unsupported Python 3.14.7/missing pypdf/wrong pypdf, literal explicit Python,
an application `.venv`, multiple PATH candidates, authored native `py -0p`
listing controls selecting the real interpreter, executable/module shadows in
book/CWD/PYTHONPATH directories, PDF without Calibre, and missing/wrong/decoy
converters. Real portable conversion succeeds through explicit and PATH selection
under both hosts and through the unchanged batch launcher. Only owned copies of
the pinned developer venv are relocated or altered for rejection controls.
The real unsupported control is the observed installed Python 3.14.7, or an
explicit `WBS_TEST_UNSUPPORTED_PYTHON` path to that exact real version. Its version
is probed before the cases; a stub cannot replace this control.

Missing/decoy converter cases alone redirect child `LOCALAPPDATA` to a fresh
owned directory with the exact preauthored empty `Microsoft/Windows/Caches`
chain, so a real per-user Calibre installation cannot satisfy their absence
premise. Held ordinary directory identities must remain unchanged; the exact
Windows closure and empty leaf are verified after the process. A separately
recorded `Python/_cache/last_welcome.txt` is permitted only when its bounded,
ordinary, single-link bytes match a new independent verified registered-manager
`list --format=exe` control. Its numeric welcome version is observed, never pinned
to one installation. That probe is test-side provenance, not runtime selection
or application/setup input; manager image bytes and parent environment remain
unchanged. Every other file/directory, reparse path, hardlink or replacement fails
the fixture. Both fixed system
Calibre paths must actually be absent;
otherwise these controls fail clearly without modifying any installation.
Parent environment, explicit wrong-version rejection and positive discovery
cases remain unchanged; no mandatory assertion is skipped.
The maintained receipt names `windows_cache_inventory_unchanged` precisely and
records the optional manager side effect separately as `manager_cache_observation`;
it does not claim the whole redirected LOCALAPPDATA stayed empty.
This test-only `converter_absence_environment` record now explicitly uses nested
`schema_version: 2`; current consumers reject the earlier shape. Historical
reports retain their original source/contract and are unchanged. This does not
change the separate legacy native acceptance report schema.

Failures must occur before console/stage/output creation and conversion, preserve
the exact source/neighbor identities, and report actual candidate probe/reason plus
exact setup targets. Success records read the application's actual prefixed
dependency/engine log records: selected absolute Python, its actual observed
accepted regular GIL Windows x64 version/build metadata, pinned pypdf import
origin, isolated probe and `-I -B -X utf8` execution
must agree. Complete reopened source page identities/content, manifests and
literal arguments are checked; real ebook outputs match an independent actual
conversion. PDF processing must leave a real converter version-spy uncalled.

Owned decoys have separate positive controls proving their execution/import
markers work. During acceptance their bytes remain unchanged and their markers
must remain absent. Exact case sets and mandatory receipts are checked by the
independent `validate_runtime_report.py`; malformed promised evidence fails.

PowerShell cases use explicit owned output bases. BAT uses the workstation's
observed Documents directory and only exact emitted, authenticated final/log
children. All cleanup uses the existing held-identity flat-file helper. Stored
policies, current source bytes, historical guards and original fixtures remain
unchanged. These are controlled actual process checks, not human Explorer,
clean-OS discovery, installation, every runtime or release-package acceptance.

M2-T05 routes preflight through the same suspended owned-job supervisor as the
engine. Its deadline includes all descendants and both pipe EOFs; successful
probe receipts require assigned job, stopped parent/tree and complete streams.
Runtime Pester independently checks the inherited-pipe child is no longer alive
after a timed-out probe. The former parent-only lifetime is historical T04
evidence. Discovery selection, compatibility predicates and strict banners are
unchanged. The fixed Python probe explicitly selects UTF-8 under isolation.
