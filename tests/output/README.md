# Current output transaction regression

Use the explicit fresh developer Python, `-I -B`, an absolute
`tests/run_tests.py` path and `--layer output --report <new external path>`.
This is the ninth full stage. It requires actual Windows and receives no shell
arguments; two controlled junction probes invoke the actual Windows PowerShell
host from SystemRoot. Only authored PDF fixtures and run-owned temporary paths
are processed.

AC-032 runs the same input twice and two different `Book.pdf` inputs in separate
source directories into one output base. All four actual CLI runs must publish
distinct complete direct children; earlier run hashes and the source/neighbor
bytes remain unchanged. Each receipt is bound to its explicit final directory,
owner marker and matching on-disk/returned manifest. Ordered filenames, ranges,
page counts, PDF hashes/sizes, exact physical page IDs and synthetic content
hashes are reopened and verified. There is no recursive PDF discovery.

AC-034 starts four fresh actual Python processes, waits for all four readiness
files, and releases one authored barrier. A worker patches only the private
timestamp seam to the same fixed value before calling the actual CLI. Distinct
PIDs, atomic run identities, final directories and complete manifests are
required. Each process owns its pipes and is bounded; only still-running owned
children can be stopped during test recovery.

AC-033 injects five controlled failures: after the first completed slice, an
unreadable output reopen, an actual valid PDF with the wrong page count,
completion-manifest writing, and final promotion. Every result must be nonzero,
claim zero successful outputs, leave no successful final directory, remove the
known owned stage, and preserve a bounded separately marked failure record.
Source and neighbor hashes remain unchanged. The harness does not claim
power-loss/crash durability or deletion of older stages.

AC-035 checks eight ownership cases: ordinary known cleanup, an unexpected
member, native prevention of held marker tampering, an untrusted manifest path,
a mocked reparse refusal, an actual junction as the output base, an actual
junction inside the stage, and native prevention of held-stage replacement.
Rejected cleanup must preserve known files and the separately owned outside
sentinel. Authored recovery removes only the exact synthetic extra member or
junction itself, then verifies normal cleanup. Junction setup and nonrecursive
removal are confined to this test's temporary tree; the target is never deleted
through the junction.

The central runner requires every promised case and meaningful actual process,
manifest, failure and junction evidence. Immutable original harnesses,
fixture/oracle guards and historical receipts stay unchanged. Current
manual/bookmark/plan/diagnostic routes use the same strict publication helper.
Explorer, Calibre, rendered fidelity and extracted-package checks remain
separate gates.

Native handles and exact identity/reparse checks reject observed ownership
changes. Compatible metadata access can still mutate an empty directory;
pre-creation checks reject an already changed stage before its owner-marker
write. Windows also requires closing child-file locks before directory rename,
followed by final byte/identity checks. Neither interval is an atomic sandbox
against an arbitrary process running as the same user. Cleanup deletes held
owned objects, never a recursively traversed target or paths from a manifest.
