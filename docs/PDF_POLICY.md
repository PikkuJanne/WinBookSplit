# Supported PDF inputs and rejection policy

WinBookSplit accepts ordinary unencrypted PDFs. The same preflight applies to
direct PDFs and PDFs generated by Calibre, before page planning, plan confirmation,
chapter reservation or writing. Rejected documents produce no chapter PDFs or
published working PDF. Ordinary processing can retain a local console log and
failure manifest; PDF Preview creates neither.

Encrypted PDFs are unsupported, including owner-only encryption with an empty
opening password. The reader rejects encryption before the PDF library reads
encryption parameters or tries a password. WinBookSplit has no PDF password
argument or password prompt and does not attempt decryption.

The following detected structures return `unsupported_document`, exit **7**:

- AcroForm and XFA, widgets, signature fields/dictionaries and catalog signature
  permissions. Signature fixtures establish structure detection, not signature
  authenticity or cryptographic verification.
- Catalog opening actions/destinations, additional actions and JavaScript name
  trees; detected active actions in copied page resources.
- Embedded-file name trees, file-attachment annotations, associated files and
  portfolios; detected embedded-file/signature objects in retained annotation
  appearances and resources.
- Rich media, Screen, Movie, Sound and 3D annotations.
- Page resources or other copied page fields that reference a document catalog
  or physical page tree. Such references can otherwise clone pages outside the
  selected chapter into hidden output objects.
  The scan includes Resources, MediaBox, CropBox and Rotate supplied by validated
  page-tree ancestors; the writer uses their effective captured page values.

Presence of a listed catalog feature is conservatively rejected even if its
value is empty. There is no promise to preserve a signature or interactive form.
Actions are inspected as PDF data and never executed.

Some excluded navigation has a narrower existing policy: page additional actions,
article threads, external or malformed links and annotation relationships are
omitted with visible categorized warnings. Static annotation values that contain
hidden page/catalog/action references are dropped by the annotation guard.
The original outline and named destinations are used for planning and supported
local link resolution, then rebuilt. Broken outlines keep their existing planning
errors, warnings and explicit fallback choices. See [PDF fidelity](PDF_FIDELITY.md).

Unreadable or truncated PDFs return `unreadable_document`, exit **6**. Invalid
page trees and zero-page PDFs return `invalid_document`, exit **6**; invalid
outline traversal returns `invalid_outline`, exit **6**. No empty successful run
is reported. Malformed generated converter output keeps
`conversion_output_invalid`, exit **4**; a generated unsupported structure keeps
`unsupported_document`, exit **7**, together with conversion/cleanup diagnostics
when owned cleanup succeeds. A secondary cleanup failure takes the existing
`conversion_cleanup_failed`, exit **4**, precedence and retains the primary
unsupported reason in its diagnostic record.

The input snapshot is limited to **512 MiB**, including the owned converter output
read. The raw page tree is inspected before the library can flatten or skip a
damaged child: each child must be a Page or Pages dictionary, counts must match,
and repeated physical pages/cycles are rejected. Supported limits are **100,000
pages**, page-tree depth **64**, and **200,000** page-tree nodes. The feature scan
has depth **128**, **200,000** visited container nodes, and bounded container
width. Existing outline and annotation inspection limits, parser limits and
process cancellation/timeout handling also apply.

These bounds do not promise a fixed memory footprint, unlimited PDF compatibility
or complete hostile-document defense. WinBookSplit is not a PDF sanitizer or a
security sandbox. Rendering engines, actual signature verification and every
possible PDF extension are outside this detection claim. Inputs remain immutable;
cleanup removes only files owned by the current run.
