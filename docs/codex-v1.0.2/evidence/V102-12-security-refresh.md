# v1.0.2 release security refresh

Fresh primary-source review on 13 October clears the unchanged reviewed package and locks for this scoped release. No source, dependency, global runtime or security setting changed.

Regular Windows x64 Python 3.15.0 remains the first stable accepted 3.15 release. Its official regular catalog hash matches the reviewed archive, and the official SBOM/final-tag NEWS identify OpenSSL 3.5.9. The retained 3.13.16/3.14.8 release records include serviced security fixes and the same OpenSSL update. Unknown minors remain unvalidated. [3.15 release](https://www.python.org/downloads/release/python-3150/), [catalog](https://www.python.org/ftp/python/3.15.0/windows-3.15.0.json), [SBOM](https://www.python.org/ftp/python/3.15.0/python-3.15.0-amd64.exe.spdx.json), [Windows update](https://raw.githubusercontent.com/python/cpython/v3.15.0/Misc/NEWS.d/3.15.0rc3.rst), [3.13.16](https://www.python.org/downloads/release/python-31316/), [3.14.8](https://www.python.org/downloads/release/python-3148/).

The fresh OpenSSL vulnerability list is byte-identical to the previously reviewed primary list. The September advisory prescribes 3.5.9 for its branch, including the HTTPS-relevant relative-CRLDP memory issue. [Current upstream list](https://openssl-library.org/news/vulnerabilities/), [September advisory](https://openssl-library.org/news/secadv/20260929.txt).

Locked pypdf 6.20.0 remains generally affected by [outline search GHSA-qfv9-64jg-mh7p](https://github.com/py-pdf/pypdf/security/advisories/GHSA-qfv9-64jg-mh7p) and [tree removal GHSA-9mx8-4j7g-633p](https://github.com/py-pdf/pypdf/security/advisories/GHSA-9mx8-4j7g-633p): both affect versions below 6.20.1 and are patched from 6.20.1. Fresh advisory/patch records are byte-identical to the earlier reviewed records. The current engine and all 59 installed wheel source files are unchanged. The direct/indirect required pipeline uses a fresh writer, excludes source annotation/tree parents, adds a new outline with default parent/before, and finalizes ordinary output without calling the affected search/removal methods. Retain the exact lock for this repair. This is scoped static reachability, not universal pypdf or hostile-PDF safety; future outline search/removal/document cloning needs renewed review. [Primary patch](https://github.com/py-pdf/pypdf/pull/4188), [locked wheel metadata](https://pypi.org/pypi/pypdf/6.20.0/json).

Calibre 9.15.0 remains the tested local unencrypted EPUB/AZW3-to-PDF tool. Current primary advisories list the conversion-option content-server issue as affecting up to 9.14 and patched in 9.15; the PalmDoc compression issue affects up to 9.12.0 and is patched in 9.13.0. The application uses neither the server nor native ebook output. The official changelog also lists 9.16; latest availability does not replace the reviewed lock. [Official advisories](https://github.com/kovidgoyal/calibre/security/advisories), [server issue](https://github.com/kovidgoyal/calibre/security/advisories/GHSA-p6rh-fpfg-37w2), [compression issue](https://github.com/kovidgoyal/calibre/security/advisories/GHSA-8rcp-ffwf-rf64), [official changelog](https://calibre-ebook.com/whats-new).

Fresh anonymous HEAD requests returned 200 and expected lengths for the exact Python archive, pypdf wheel and Calibre portable asset. Catalog/PyPI hashes still match. These requests establish current availability only. Actual native tests, public publication, fixed tag, anonymous downloaded byte equality and final main synchronization remain their own evidence.
