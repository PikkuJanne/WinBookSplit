## Changes and boundary

`engine/WinBookSplit.Runtime.ps1` now queries the exact current-user package name
without a publisher filter, then validates each complete Store or python.org
publisher/PublisherId/family/signature tuple. Cross-pairing is rejected. Exact
schema/boolean flags, x64/status, unique full package names, and physical package
location checks remain. Version components are canonical unsigned 16-bit values;
the captured manager version is not an allowlist.

The eligible entry point is the documented KnownFolder
`Microsoft/WindowsApps/<family>/pymanager.exe`. Its parent chain uses the unchanged
ordinary path guard, and package/alias locations retain book/CWD exclusions.
Only the documented AppExecutionAlias reparse tag is read using FSCTL; payload
strings are not parsed or trusted. Ordinary files, hardlinks, junctions and
unverified PATH names gain no exception. Generic runtime and converter guards
are unchanged.

`Get-WinBookSplitRegisteredManagerPaths -WithRegistration` optionally returns
`{Path,Package}` descriptors; its default path return remains compatible.
`Invoke-WinBookSplitManagerListing` revalidates the descriptor and invokes only
`list --format=exe`. `engine/WinBookSplit.Process.ps1` adds a narrow package-bound
launch to the existing supervisor: after Windows resolves the alias, the primary
thread is still suspended. Supported `GetPackageFullName` and
`QueryFullProcessImageNameW` must match the exact validated registration and
physical pymanager image before resume. A mismatch terminates the suspended
child. Existing job ownership, cancellation, finite deadline, descendant stop,
argument quoting, child install-disable environment and stream handling remain.
Rejected pre-resume children have no EOF/drain proof; StreamsComplete remains
false truthfully. Successful listing requires the existing complete-stream rules.

## Identity/source verification

confirms both family entry points and discourages direct Program Files launch.
Its [listing section](https://docs.python.org/3.15/using/windows.html#listing-runtimes)
documents installed-only `list --format=exe`; online/source operations are
separate. Discovery requests neither install/exec nor index retrieval. Manager
listing may produce bounded local logs; zero filesystem writes is not claimed.

The [official appinstaller](https://www.python.org/ftp/python/pymanager/pymanager.appinstaller)
and real current-user package reconfirmed the python.org tuple/version/x64.
[Microsoft Store product metadata](https://storeedgefd.dsx.mp.microsoft.com/v9.0/products/9NQ7512CXL7T?market=US&locale=en-us&deviceFamily=Windows.Desktop)
(revision 2026-10-09) reconfirmed the Store family and PSF distribution. Exact
Store publisher/signature evidence remains the captured owner registration;
catalog metadata is not signature-kind evidence. The
[official CPython layout source](https://github.com/python/cpython/blob/main/PC/layout/support/appxmanifest.py)
also carries the Store publisher GUID. The
[manager manifest](https://github.com/python/pymanager/blob/main/src/pymanager/appxmanifest.xml)
declares Pymanager.Exe, physical pymanager.exe and its alias. No Store package is
installed on this host and no synthetic flags are labelled observed.

Binding APIs: [GetPackageFullName](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getpackagefullname),
[QueryFullProcessImageNameW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-queryfullprocessimagenamew).
