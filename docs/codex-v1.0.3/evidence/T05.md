## Changes and purpose

The maintained builder defaults its generated launcher explicitly to
store-existing without prerequisite provisioning. After kit authentication this
route rejects supplied runtimes, activated/injected Python configuration and
prebuilt app environments. A missing/rejected/empty existing Store inventory
blocks before any private acquisition, copy, clone or tooling bootstrap. Its
independent installed-only registration/listing/probe inventory is verification
and helper-bootstrap evidence only. Fresh application discovery and normal setup
BAT receive no selected interpreter or environment overrides. Discovery itself
must complete a bound Store manager listing and choose a verified pre-existing
concrete member. Normal setup may then create the app-local venv and install the
locked pypdf. The venv base must match that automatically discovered member.

The separate legacy-explicit scenario keeps its existing private/supplied-runtime
recipes and schema1 consumer. Historical reports remain unchanged. They cannot
satisfy the new schema2 Store gate, which rejects attempted fallback even unused,
supplied/copied/cloned/injected runtimes, inventory used as selection and
contradictory structured application argv/environment/process evidence.

The collector reuses the production job/stream supervisor and writes bounded,
exclusive BOMless UTF8 JSON with explicit exit/failure status. It avoids native
stderr forwarding through a nested PowerShell pipeline. Failed Store stages
return sanitized technical observations, rejected interpreter probes and NOT_RUN
records for later stages in native-store-result.zip. The return archive accepts
only the seven known report/receipt members and holds ordinary file leases.
Original native stream totals and hashes remain separate from measured redacted
text lengths. Redaction handles case, dictionary keys, nested JSON and escaped
paths. The additional offline checker still verifies consistency rather than
attesting physical execution; native receipts and application oracles require
independent review.

Preservation observes manager registration/image and alias reparse bytes, PATH,
chosen runtime bytes, controller environment and base distribution metadata before
and after. Package preservation compares names/versions/locations, not every
global file. Extracted production files remain leased and are rehashed against
the exact extraction receipt; authenticated helper/fixture closures are rechecked
before any pass. No product engine/runtime/setup or policy bytes changed in T05.
