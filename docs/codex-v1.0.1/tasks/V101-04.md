# V101-04 — Harden launcher discovery and independent fallback

Milestone: M1. Prerequisites: V101-03

## Read

- [specs/DISCOVERY_AND_SETUP.md](../specs/DISCOVERY_AND_SETUP.md)

## Work

Extend the current resolver; keep explicit path and app .venv authoritative. Add tested installed-only manager/legacy listing detection and direct PATH discovery. Keep selection deterministic, bounded and origin-validated. Reproduce the exact unknown -0 launcher output through a fake bounded executable/probe and demonstrate later valid discovery. Do not bypass trust rules for aliases wholesale. Manager/launcher failure should be quietly informative on eventual success.

## Acceptance

- **V101-AC-017:** Legacy installed-only launcher listing works and parses concrete executable paths safely.
- **V101-AC-018:** Installed Python manager listing is handled through a verified read-only route, without runtime install triggers.
- **V101-AC-019:** Unknown option -0 does not prevent a subsequent trusted PATH interpreter from succeeding.
- **V101-AC-020:** No launcher plus a valid direct interpreter works; empty/malformed listings are bounded failures rather than hangs.
- **V101-AC-021:** Invalid explicit Python or broken existing .venv fails without silently switching runtimes.
- **V101-AC-022:** Document/CWD decoys, import shadowing and unsafe executable aliases remain excluded; valid unrelated-CWD launch still works.
- **V101-AC-023:** Discovery never launches an installer, changes global settings, queries online runtime lists or hangs indefinitely.
- **V101-AC-024:** Multiple valid candidates are deduplicated and selected deterministically; diagnostics identify the actual choice.
