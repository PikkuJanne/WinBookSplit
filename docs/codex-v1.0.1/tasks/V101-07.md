## Read

- [TESTING.md](../TESTING.md)

## Work

Reuse the existing test runner and fixtures. Add the new acceptance cases; update obsolete tests that intentionally require exact Python/Windows11 but do not delete safety assertions. Keep reference fixture/render generation on a reviewed toolchain and run actual application tests under every candidate minor. Fix native dev-wheel constraints without forcing those wheels into application environments. Record why a proposed minor cannot be supported if a real blocker remains.

## Acceptance

- **V101-AC-039:** Every advertised Python minor runs actual application tests; at least two pass. Mocked versions are separate policy tests.
- **V101-AC-040:** Existing full Python and PS5.1/PS7 reference regression passes with no unexplained removal of safety tests.
- **V101-AC-041:** Reference developer wheels/tool pins do not recreate an application exact-Python requirement or get installed into runtime-only environments.
- **V101-AC-042:** Synthetic/redistributable fixtures cover page boundaries, metadata policy and conversion; no personal documents enter tests.
- **V101-AC-043:** Data-driven tests cover both later patches and blocked/security floor cases without claiming all were actually installed.

## Checkpoint and continuation
Record actual commands, source/package identity, outcomes and limitations in a brief redacted evidence file under `evidence/`. Update TASKS/ACCEPTANCE_CASES/STATUS/NEXT_SESSION. Commit only intended files, push normally and verify clean HEAD against the freshly queried live remote branch. A prior receipt does not certify a later commit. Then continue the next ready task rather than asking the owner to approve another ordinary milestone.

No private documents, fabricated evidence, unapproved infrastructure or destructive Git commands. Human testing is governed by HUMAN_TESTING.md, not the old v1.0.0 checklist. If this task is genuinely blocked, identify the exact dependency and complete independent work first.
