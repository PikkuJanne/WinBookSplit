# M3-T01 — Propagate outcomes and cancel safely

Status is canonical in `../TASKS.json`; the initial state is todo.
Dependency: M2-T05.

## Outcome

Make success, failure and cancellation truthful through the batch entry point.

## Read

Applicable AGENTS.md, STATUS.md, NEXT_SESSION.md, SCOPE_AND_DECISIONS.md and:

## Work

1. Apply one result/exit-code mapping and capture the final fallback attempt rather than the first failure only.
2. Remove unconditional success, preserve native result through cleanup and launcher pause behavior.
3. Implement cancellation/timeout and process ownership without killing unrelated Python/Calibre processes.
4. Test startup/write/conversion/fallback failures and marked partial/staging handling.

## Deliverables

- End-to-end result/exit semantics
- Safe cancel/timeout
- Failure propagation tests

## Acceptance

- **AC-050: Failure and fallback exit propagation.** Fail original mode, successful fallback, failed fallback and failed converter via .bat and .ps1. Expected: Exit reflects final attempted operation; no unconditional Done/success; batch preserves nonzero failures.
- **AC-051: Cancel only owned processes.** Start unrelated Python process, then cancel splitting/conversion and exercise timeout. Expected: Owned child tree terminates/cleans safely; unrelated process survives; cancelled result and no final successful output.
- **AC-052: Cleanup and finalization failures.** Inject cleanup, log/manifest finalize and publish-folder rename failure. Expected: Truthful failed/incomplete result, no clobber or hidden success; recoverable diagnostics without deleting unrelated files.
