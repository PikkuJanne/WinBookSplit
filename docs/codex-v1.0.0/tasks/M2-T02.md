## Work

1. Use literal file-only validation and resolved provider paths throughout PowerShell.
2. Build safe Unicode titles, full-path-aware truncation, stable fallbacks, case-insensitive collision checks and dynamic numbering.
3. Test special characters, unreadable/unwritable paths, long paths and 100+ sections.
4. Preserve source filenames/paths; never alter machine-wide path/security settings.

## Deliverables

- Literal-path handling
- Safe deterministic filenames
- Windows-path tests

## Acceptance

- **AC-036: Literal Windows input paths.** Test directories ending .pdf, paths with spaces/brackets/apostrophe/ampersand/parentheses and mixed extension case. Expected: Directories rejected; valid files treated literally and parser verified; no wildcard matches to another source.
- **AC-037: Filename sanitation.** Titles contain forbidden/control characters, trailing dots/spaces, reserved names, only punctuation and non-ASCII text. Expected: Safe contained filenames, stable fallback, Unicode retained, no traversal or overwrite.
- **AC-038: More than 99 chapters.** Generate 120 valid sections and inspect lexical ordering. Expected: 001..120-style width, stable chronological lexical order and unique filenames.
- **AC-039: Long/unwritable destinations.** Test full path budget and unwritable/full target simulation. Expected: Safe full-path-aware shortening or early actionable rejection; no machine policy changes or source writes.
